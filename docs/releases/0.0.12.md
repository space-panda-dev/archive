# Specification 0.0.12: capture starts

[Specification 0.0.12](../../spec/0.0.12/archive-spec.md) adds
`archive.claim/capture_start` version 1 from accepted
[ADR 0107](../decisions/0107-multi-device-and-live.md). All 0.0.11
bundles retain their exact bytes. D-20 defines the closed payload, Artifact
pin, clock pairing, calendar validation and asserter rules.

World projection 6 revision 9 projects each statement in its own claim
graph. Native capture proposes the recorder grammar's wall time per
recognised file. For files without a source reader it proposes no clock
evidence; a session label or Door admission time never supplies one.
A repeat import skips content already belonging to sessions. Known content
without a session can be adopted using the recorder grammar (ADR 0070); this
is separate from legacy grouping translation. Member allowlists are unchanged in this release.

Existing archives adopt the additive release through the specification
upgrade. This code change does not upgrade any archive or deploy services.

The same additive release includes ADR 0120's `session_ensemble` version 1,
asserted only by the active operator and projected in its own claim graph.
It is separate from artist billing. Missing and competing associations
remain explicit; membership and relay configuration never fill them.

ADR 0121 adds `archive.migration/session_translation` version 1 for durable
source-snapshot-to-session/parts provenance. The explicit read-only command
`python -m migration.legacy_sessions` prepares proposals for missing legacy
sessions, preserving explicit source/file order and reporting unresolved
ambiguity. It admits nothing. See the
[backfill procedure](../legacy-session-backfill.md).
