# Specification 0.0.11: release notes

Specification [0.0.11](../../spec/0.0.11/archive-spec.md) installs seven
contract versions beside every 0.0.10 bundle with its exact bytes: the six <!-- lens: allow stale -->
of [ADR 0113](../decisions/0113-editing-lead-sheets.md), the lead-sheet
editor (melody version 2 and its sketches, form version 2's open repeats,
form spans version 2's passes and returns, meter layers version 3, the
underlay, and lead sheet version 2), and export version 2 of
[ADR 0116](../decisions/0116-ireal-charts.md), whose written directions
also ride in meter layers version 3. Section D-19 states their rules. The layout is
`archive/2` and the core context and Entity kinds are 0.0.10's, so a 0.0.10 <!-- lens: allow stale -->
archive adopts it by the specification upgrade (D-15).

## Amended before release (2026-10-22)

The operator accepted [ADR 0116](../decisions/0116-ireal-charts.md), iReal
Pro charts, before 0.0.11 was cut. Following 0.0.10's precedent, its two <!-- lens: allow stale -->
contract changes are folded into this release; the unreleased bundles were
changed in place, and the earlier draft digest was never released.

- **Written directions** (decision D): an untimed bar of meter layers
  version 3 may carry `directions`, 1 to 8, each `text` (1 to 200
  characters, never a lyric line) and an optional `tempo` in ADR 0106's
  target-tempo shape. A timed bar never carries them. The bundle's digest
  changed from the draft
  `sha256:59f2cc8625e587f9abc319e16a70e941c999bad0b0495e69ba263ee3d0b22910`
  to the one in the table. World checks directions (`world/form.py`),
  projects them (revision 8 of projection 6), and writes them in MusicXML
  as `<direction>` with `<words>` and `<metronome>` and in LilyPond as
  `\tempo` and `\mark`.
- **The `ireal` format** (decision E): `archive.claim/export` version 2 is
  version 1 plus format `ireal` (`text/plain`, `.irealb`), new in this
  release. ADR 0089's format table is amended. World checks a request
  against every format and a claim against its version's formats;
  exporter `lead-sheet-ireal` version 1 (`documents/ireal/export.py`) can
  be configured on the relay.
- **The iReal importer now writes directions:** each chart's style (with
  its tempo when it is non-zero) on the first bar, and each comment on its
  bar, into meter layers version 3, so it needs an archive at 0.0.11. Its
  links write lead sheet version 2, which can pin that meter. The parameters
  digest changed, so a rerun over charts read before reads them again.
  `enrich align` accepts an untimed meter of version 2 or 3 and writes the
  timed meter at the same version.

## Profile rules

Two rules are new, and Door enforces both rather than refusing records that
cite them as pending:

- `x-archive-placed-items`: across a payload, in document order, the
  integers in each placed unit's `items` strictly increase, so words never
  share or cross notes.
- `x-archive-pass-lists`: every array a named path reaches is distinct
  ascending pass numbers, optionally followed by `last`, or `last` alone.

`x-archive-form-structure` is widened to check an open repeat's endings: one
last-time ending, one default, and the others of distinct ascending pass
numbers. A version 1 form means what it meant.

## Decided while implementing

These choices were made while building 0.0.11 and are for the operator to
confirm:

- **Meter layers version 3 stays the operator's.** ADR 0113's member
  contracts are melody 2, the underlay, form 2, form spans 2, and lead sheet
  2; meter layers 3 is not one, so World's circle and Door's member list do
  not name it. A later amendment may. The underlay's locators are checked
  against the document by the editor's adapter before it proposes, not by
  the relay.
- **A span's return is always true.** Form spans version 2's bundle makes a
  span's `return` const `true`; World now refuses `false` as Door does.
- **Played sections and bars, version 2.** `played_sections` and
  `played_bars` gain version 2, which reads form 2 and meter layers 3 and
  marks an entry open when it is played in the pass standing for an open
  repeat's further passes; version 1 answers as 0.0.10 served it. The <!-- lens: allow stale -->
  folded chart is the named view `folded_chart`.
- **A direction's tempo is 1 to 999.999.** The bundle's `bpm` pattern is
  ADR 0106's: decimal text from 1 to 999 with at most three places and no
  trailing zero.
- **"Never a lyric line" is stated, not checked.** A bar names no lyric, so
  neither Door nor World can tell; the asserter keeps it.
- **Exports of a direction's tempo.** A tempo with no `beat` counts the
  bar's beat (its denominator) in MusicXML and LilyPond. LilyPond writes
  whole beats a minute, so it rounds a fractional tempo and lists the loss.
  The iReal exporter writes the first bar's first direction as the style
  and tempo fields (a tempo outside iReal's 40 to 300, fractional, or in
  another beat is a loss), and every other direction as a comment.

## Moved again

The 0.0.10 notes moved three things to 0.0.11. None of them is built in <!-- lens: allow stale -->
0.0.11, so each moves again unless the operator decides otherwise:

- **The practice renderer and the exporters.** No renderer is built, and
  no PDF, MusicXML, LilyPond or JAMS exporter program; a practice render
  still answers `renderer_unknown`. The one exporter built is ADR 0116's
  `lead-sheet-ireal`, which a relay runs only when it is configured.
- **Forced alignment.** No aligner ships; the `timed-lyrics` proposer still
  answers `not_yet`. (`enrich align`, from ADR 0116, places a chart's
  untimed claims on machine beats; it does not align lyrics.)
- **Rhythm 5.** Downbeats from Beat This are not started; rhythm 4 stays,
  and the `written_rhythm` view still gives every note `bar: null` unless
  the reader asks for meter `layer: 1`.
